# Phase 0 research memo — synthguard

This memo is generated by `research/phase0/render_docs.py` from harness
`results.json` files. Narrative is the template; every quantitative claim is
substituted from those files. Re-run `make research` after changing a harness.

**Safety.** DETECTION ONLY. This project never generates, completes,
optimizes, or suggests sequence modifications. There is no generative
component. Phase 0 commits benign public-style sequences only. No hazardous
sequences are constructed or referenced.

---

## §1 Problem statement

DNA synthesis providers are asked to screen incoming orders for sequences
that should not be made. The public conversation jumps to BLAST databases of
regulated agents. This repository does not do that in Phase 0 and will not
commit those sequences.

The people who pay for a missing open gateway are providers who only have a
vendor-closed screen, researchers who cannot audit a false-positive rate on
ordinary lab DNA, and customers whose housekeeping-gene orders get blocked
because a threshold was never measured.

This repo implements a local identity / k-mer scorer, a minimum-length gate,
and an overlap graph for split orders. It reports detections. It does not
propose a rewritten sequence that would clear.

## §2 Prior art

| Tool | What it does | Gap |
| --- | --- | --- |
| [IGSC / provider screens](https://github.com/InternationalGeneSynthesisConsortium) | Industry screening norms | Closed implementations; FPR on benign DNA not a public artifact |
| BLAST / DIAMOND | Homology search | Needs a sequences-of-concern database this repo will not bundle |
| HMMER | Profile search | Same database problem; deferred |
| Split-order papers | Graph reassembly of tiled oligos | Rarely shipped as an open, tested fixture with a negative control |
| Generative DNA models | Propose sequence edits | Out of scope. Forbidden here. |

Something already "solves" synthesis screening: every large provider runs a
closed pipeline. Another tool is still worth building because (1) the benign
FPR is not a public, replayable number, (2) split-order detection needs a
negative control, and (3) an open gateway must refuse to become a designer.
The product is a detection, not a redesign.

## §4 Technical selection

Each choice below is expensive to reverse. Options, criterion, measurement,
decision.

### 4.1 Default identity threshold

Options: 0.70, 0.80, 0.90, 0.95, BLAST default 0.80 bit heuristics.

Criterion: FPR ≤ 0.05 on 200+ benign queries when the benign panel is treated
as a stand-in hit list. Exact backbone matches are annotated CLEAR and are
not the FPR numerator in the sample path; the harness uses raw identity.

Measurement: `research/phase0/benign_fpr/` (n=220).

| threshold | flagged | n | FPR |
| --- | --- | --- | --- |
| 0.70 | 40 | 220 | 0.182 |
| 0.75 | 18 | 220 | 0.082 |
| 0.80 | 0 | 220 | 0.000 |
| 0.85 | 0 | 220 | 0.000 |
| 0.90 | 0 | 220 | 0.000 |
| 0.95 | 0 | 220 | 0.000 |
| 0.99 | 0 | 220 | 0.000 |

Decision: **Lowest threshold with FPR ≤ 0.05 is 0.80 (FPR 0.000). Phase 0 default remains 0.90 (FPR 0.000). Recommend moving the default to 0.80 in Phase 1.**

SOC-database TPR: **unmeasured** (no SOC sequences).

### 4.2 Homology backend

Options: naive window identity; k-mer prefilter then identity; BLAST;
DIAMOND; HMMER.

Criterion: wall time on synthetic benign queries at several lengths and
volumes. External tools are deferred until a SOC database exists.

Measurement: `research/phase0/screening_latency/`.

Faster backend = indexed. Indexed 1.5656s vs naive 1.5969s.

Decision: **Local indexed backend is faster on this grid (indexed 1.5656s vs naive 1.5969s total). BLAST vs DIAMOND vs HMM remains deferred. BLAST RTT: unmeasured.**

### 4.3 Split-order detection

Options: ignore multi-order; per-requester overlap graph; full de Bruijn
assembly (would reconstruct sequence — rejected).

Criterion: detect R001's five overlapping fragments of one benign gene;
do not flag R002–R004 unrelated fragments.

Measurement: `research/phase0/split_order_sim/`.

R001 detected=True. Control FP=0/3.

Decision: **Split-order graph is in scope for Phase 2: R001 detected and 0 of 3 control requesters flagged.**

A de Bruijn assembler would reconstruct bases that the customer did not
submit in one order. That is out of scope.

## §5 Evaluation design

Hold-out (Phase 3, not run here): a licensed SOC set held outside git, plus
a larger benign set. This repository still must not commit hazard sequences.

Metrics, declared before any SOC database is attached:

- FPR on benign DNA at the chosen threshold
- Latency p50/p95 of the local backend
- Split-order recall on R001-style tiles
- Split-order FPR on unrelated multi-order customers
- TPR on SOC: **unmeasured** here

Split: committed seeds. No random reshuffle in CI.

**Failure condition (written before the answer):** the project fails if
benign FPR at the shipped threshold exceeds 0.05 on the Phase 3 benign
hold-out **or** if any control requester in a R001-style fixture is flagged
**or** if the software emits a modified sequence.

## §6 Cost and scale model

Local CPU only. No API. Numbers:

- Benign queries scored: 220
- Mean identity vs benign panel: 0.533
- Default threshold 0.90 FPR: 0.000
- Indexed backend total on the latency grid: 1.5656s
- Naive backend total on the latency grid: 1.5969s
- BLAST / DIAMOND / HMM RTT: unmeasured
- USD / order: unmeasured (no API)
- Split-order R001 reconstructed fraction: 1.000

Unmeasured: BLAST cloud cost, licensed SOC-DB licensing, human reviewer
time. The measurement that would settle BLAST cost is a timed local BLAST
of the 200 benign queries against a public benign-only subset, recorded as
seconds — still without a hazard database.

## §7 Risks

| Risk | Type | Mitigation or acceptance |
| --- | --- | --- |
| Benign panel used as if it were a SOC database | Scope | Memo and code say stand-in. Sample path never auto-flags known backbones. |
| Someone adds a sequence completer | Safety | CONTRIBUTING forbids it. CLI is demo-plan only. |
| Near-miss benign homolog auto-flagged | Technical | Default threshold vs measured identity. Sample near-miss must CLEAR. |
| Too-short oligos treated as cleared | Safety | Length < 50 is NOT SCREENABLE, exit 1. |
| Reconstructing a gene from tiles | Scope | Graph detects overlap; it does not emit the parent sequence to the user. |
| Live GenBank pull drifts into hazard neighbors | Legal | No live pull in Phase 0. |

### Highest-risk technical unknowns going into Phase 1

1. Whether a licensed SOC set, never committed here, keeps TPR usable at
   the threshold chosen from benign FPR (TPR **unmeasured**).
2. Whether the k-mer prefilter still beats naive scan at provider volumes
   (Phase 0 grid is demo-scale).
3. Whether customers who legitimately order overlapping benign fragments
   of a cloning project create an unacceptable split-order false-positive
   rate (only the designed control is measured here).
